## 結論から

業務で機密情報を扱うなら、使う順序はこうなります：

1. **ローカルQwen3（Ollama等）** — 唯一リスクゼロ
2. **ChatGPT / Claude API・Enterprise** — オプトアウト設定後に許容
3. **Gemini Workspace（法人契約）** — 法人契約であれば許容範囲
4. **ChatGPT / Claude 一般プラン** — 設定確認が必須
5. **Kimi（Moonshot AI）** — 業務機密には**使用非推奨**

設計書、ソースコード、顧客情報、インシデントログをLLMに投げている人は、一度この記事を読んでください。

## 各LLMの詳細ポイント

### ChatGPT（OpenAI）

Free・Plus・Proプランではデフォルトで会話が学習に使われます。オプトアウトは「設定 → データコントロール → モデル改善をOFF」で可能ですが、一度学習に使われたデータは削除できません。

米国の CLOUD Act に基づき、法的要請があれば政府機関へのデータ開示義務が発生します。

### Gemini（Google）

サインイン状態での会話は学習に使われます。オプトアウトには「一時チャット使用」または「スマート機能の無効化」が必要です。

Workspace（法人）版は組織外での学習利用がデフォルトで禁止されています。個人アカウントではデータを削除しても内部ログが残る可能性があります。

### Claude（Anthropic）

2025年10月8日以降、消費者向け全プラン（Free/Pro/Max）でデフォルトで学習に使用されるよう変更されました。データ保持期間が最大**5年**に延長されている点も注意が必要です。

米国の連邦裁判所では「Claudeには守秘義務がない」として弁護士・依頼人間の特権が消滅するとの判決も出ています。

### Kimi（Moonshot AI）

このリストの中で**最もリスクが高い**選択肢です。Moonshot AIは中国企業であり、**中国国家情報法**により、中国当局から要請があればユーザーデータを提供する法的義務を負います。

プライバシーポリシーには「AIモデルの改善・学習にユーザーコンテンツを使用する」と広範な同意条項が含まれており、国際ユーザー向けのオプトアウト手順も不明確です。

業務情報・顧客情報の入力は避けるべきです。

### ローカルQwen3（Ollama等）

**唯一リスクゼロの選択肢**です。モデルをローカル実行することでデータが外部に一切送信されません。GDPR や HIPAA などのコンプライアンスも自己管理で対応可能です。

ただし、**Qwen Chat（クラウド版）を使う場合は中国（Alibaba）サーバーへのデータ送信が発生**します。「Qwen = 安全」ではなく、**Ollama等でのローカル実行が前提**です。

## エンジニアが特に気をつけるべきこと

LLMを業務で使うシーンは増えています。しかし「機密情報をそのまま貼り付ける」という使い方は思った以上にリスクがあります。

**注意が必要な入力データの例：**

- ソースコード・設計書・仕様書
- 設定ファイルの断片（ホスト名・認証情報が含まれやすい）
- インシデントログ・障害報告書
- 顧客情報・契約情報
- 社内Wikiやドキュメントの貼り付け

一般プランで学習がONのまま使っていると、これらが学習データになる可能性があります。

**対策の優先順位：**

1. 即時：使っているLLMのオプトアウト設定を確認する
2. 機密情報はローカルLLM（Ollama + Qwen3等）に移す
3. 組織内利用はEnterprise/APIプランに統一する

## まとめ

どのLLMを使うかは、何を入力するかと切り離せません。

個人的な技術調査や雑談的な利用であれば、どのLLMを使っても実害は少ないでしょう。問題は、業務の文脈で「とりあえず貼り付けてみる」が積み重なった時です。

ローカルLLMはセットアップのハードルこそありますが、一度動かせばランニングコストゼロ・プライバシーリスクゼロです。Mac mini や普通のPCでも十分に動きます。

機密情報を扱うなら、ツールの選択基準に「どこにデータが行くか」を加えてください。
