AIエージェントを実務に入れると、何でも自動化できるように見えます。
自分も最初はかなりそう思っていました。

でも実際に回してみると、印象は少し違いました。速くなる作業は確かにある一方で、向いていない仕事に無理に入れると、むしろ確認コストが増えます。

この記事では、OpenClawを実務で動かして見えてきた **AIエージェントに向く作業 / 向かない作業 / 安定運用に必要だったこと** を整理します。

---

## 結論：AIエージェントは「何でもやる人」ではなく「流れが決まった仕事を加速する人」

結論から言うと、AIエージェントは **「考えなくていい仕事の代行」** ではなく、**「流れが決まっている仕事の加速装置」** として使うのが一番効きました。

特に相性が良かったのはこのあたりです。

- 定期チェック
- 情報収集と整理
- 下書き作成
- リマインド
- 既知フローの自動実行

逆に、曖昧な依頼や一発で正解が必要な仕事はあまり向いていませんでした。

---

## 向いていた作業

### 1. 定期チェック

一番相性が良かったのはここです。

たとえば、

- 利用料金の定期確認
- システム状態の確認
- セキュリティチェック
- 進行中タスクの見直し
- 定時の通知やリマインド

のように、**毎回やることはほぼ同じで、見るポイントが決まっている作業** はかなり強いです。

人間がやると忘れがちなものほど向いていました。

OpenClawだと、heartbeat や cron を使ってこのあたりを自然に回せます。しかも「異常があった時だけ知らせる」形にしやすいので、通知疲れも起きにくいです。

### 2. 情報収集と整理

検索して終わりではなく、

- 必要な情報だけ抜く
- 要点を整理する
- 次の判断材料に変える

このあたりも相性が良いです。

特に、全部読むのは重いけれど叩き台は欲しい、という作業でかなり助かりました。

単なる要約より、**「次に何を見るべきか」まで並べさせる** と使いやすくなります。

### 3. 下書き作成

公開前の完成稿ではなく、**構成案や初稿を出させる** 使い方はかなり実用的でした。

ゼロから書き始める負担が減るので、人間側は「直す・足す・削る」に集中できます。

実際、記事やメモ、比較表、調査の叩き台のようなものは、最初の空白を埋める役としてかなり優秀です。

### 4. 既知フローの自動実行

「入力が来たらこの順番で処理する」「終わったら記録する」といった、ある程度型の決まった作業も向いていました。

ここで大事だったのは、AIの自由度を上げすぎないことです。

```text
良かったケース:
- チェック項目が決まっている
- 保存先が決まっている
- 報告形式が決まっている

危なかったケース:
- ゴールだけ渡して、やり方を丸投げ
- 成功条件が曖昧
- 記録を残さない
```

AIが強いというより、**流れが固定された仕事と相性が良い** という感覚でした。

---

## 向かなかった作業

### 1. ゴールが曖昧な仕事

「いい感じにやって」が一番危険でした。

AIはそれっぽく前に進めますが、そもそもゴールが曖昧だと、間違った方向に綺麗に進みます。

これは便利さの裏返しで、雑な指示でも止まらずに進めてしまうからです。

### 2. 一発で正解が必要な判断

たとえば、

- 投資判断
- 外部送信
- 削除系の操作
- 設定変更

のように、失敗コストの高い処理は最後まで人間の確認が必要でした。

AIに任せる価値がないわけではありません。むしろ、選択肢整理や下調べまではかなり役立ちます。

ただ、**最終承認まで自動化すると怖い領域** は明確にあります。

### 3. 文脈依存が強い最終調整

細かいニュアンス、相手との関係性、公開文の温度感など、最後のひと押しはまだ人間の方が強いです。

特に外部に出る文章は、正しいだけでは足りません。

- どこまで断言するか
- どういう順番で伝えるか
- 読み手がどう受け取るか

このあたりは、最終的には人間の手を入れた方が自然になりました。

---

## 使ってみて分かったこと：重要なのはモデル性能より運用設計

実際に回してみて痛感したのは、重要なのはモデル性能より **運用設計** だということでした。

たとえば以下です。

- どこまで自動化するか
- どこで止めるか
- 何を記録するか
- 異常時にどう戻すか
- 誰が最終確認するか

この設計がないと、AIは便利というより不安定になります。

逆にここを固めると、かなり安心して任せられます。

### 実際に効いたルール

自分の環境では、次のようなルールがかなり効きました。

- 3ステップ以上の作業は todo に書く
- 重要な内容は memory に残す
- 外部送信や削除は確認を挟む
- 定期処理は heartbeat と cron を使い分ける
- 「何をもって成功か」を先に決める

派手ではないですが、このあたりを固めるだけで挙動がかなり安定します。

---

## じゃあ実務ではどう使うべきか

今のところ、自分の中ではこの分担がしっくり来ています。

| AIに任せる | 人が持つ |
|---|---|
| 定期処理 | 最終判断 |
| 調査 | 外部公開 |
| 整理 | 重要変更の承認 |
| 初稿作成 | ニュアンス調整 |
| 叩き台づくり | 例外時の判断 |

要するに、AIを「全部やる人」として扱うより、**前工程を進める有能な実務補助** として置く方が安定します。

これは期待値を下げる話ではなく、むしろ逆です。

役割を絞った方が、AIはかなり強くなります。

---

## OpenClawが実務投入しやすかった理由

OpenClawが使いやすかったのは、単にチャットできるからではなく、**運用前提の部品が揃っていた** からでした。

たとえば、

- ファイルを読んで文脈を維持できる
- memory に継続情報を残せる
- heartbeat で定期確認ができる
- cron で正確な時刻実行ができる
- browser / web_search / exec などを役割に応じて使い分けられる

このあたりが最初からつながっていると、「試しに使う」から「仕事で回す」へ移りやすいです。

特に良かったのは、**会話だけで終わらず、記録と実行が同じ流れに乗ること** でした。

---

## まとめ

AIエージェントを実務に入れて分かったのは、「何でも自動化できる」ではなく、**流れが固まった仕事ほど強い** ということでした。

派手なのは完全自動化ですが、実際に効いたのはむしろ地味な部分です。

- 毎回やる確認
- 抜け漏れしやすいチェック
- 面倒な整理
- 下書き作成

このあたりを任せるだけでも、かなり前に進みます。

個人的には、AIの価値は「人を消すこと」より **人の注意力を温存すること** にあると感じています。

AIエージェントを触り始めたばかりの人ほど、まずは大きな自動化ではなく、**定期チェック・整理・下書き** のような小さくて効く仕事から入るのがおすすめです。
