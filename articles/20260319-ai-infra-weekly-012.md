## 1. Edge.js — WasmサンドボックスでDockerなしにNode.jsを動かす

**Source: Publickey / Wasmer Blog (2026-03-18)**

Wasmerが発表した **[Edge.js](https://edgejs.org/)** は、WebAssemblyランタイム上でNode.js互換の実行環境を提供する新しいプラットフォーム。Docker・コンテナなしに任意のNode.jsアプリをWasmサンドボックス内で安全に動かせる。

**注目ポイント：**

- **Node.js完全互換**：既存コードを改変せずそのまま動作
- **コンテナより高密度**：1ホストあたりの多重起動数でDockerを大幅に上回ると主張
- **MCP・AIエージェント対応**：JS製のMCPサーバーやAIエージェントをサンドボックス実行できる点が実務上大きい
- **起動速度**：コールドスタートがコンテナ比で数百ms単位で速い（ミリ秒〜）

**インフラ目線の所感：**

「コンテナレスの実行基盤」はFaaS文脈では既にある話だが、Node.js完全互換＋Wasmサンドボックスの組み合わせは新しい。特にAIエージェント周辺でNode.jsのMCPサーバーを大量に生やす構成では、Dockerオーバーヘッドなしで動くのは魅力的。本番採用にはエコシステムの成熟度確認が必要だが、PoC段階では試す価値がある。

## 2. Claude Opus 4.6、Firefoxの脆弱性を22件自律発見 — AIセキュリティ自動化の現実

**Source: InfoQ (2026-03-19)**

AnthropicのClaude Opus 4.6が**2週間でFirefoxの脆弱性を22件発見**した。うち14件が高深刻度（High severity）で、さらに2件については動作するエクスプロイトコードまで自動生成している。

**数字で整理：**

| 指標 | 値 |
|---|---|
| 検出脆弱性数 | 22件 |
| High severity | 14件（63%） |
| エクスプロイト生成 | 2件 |
| 期間 | 2週間 |
| 対象 | Firefox（OSS）|

**何が変わるのか：**

従来の脆弱性スキャンはルールベース or ファジング。今回のようにAIが**コードを読んで意味的に脆弱性を推論し、エクスプロイトまで書く**のは質が違う。セキュリティチームにとっては強力な武器になるが、同じことを攻撃者もできる、ということでもある。

ネットワーク・インフラエンジニア視点では「業務でFirefoxベースのWebUIを使っている機器・システム（IPMIコンソール、ルーター管理画面など）」は特に要注意。

## 3. データセンターが戦場になった — 中東紛争とクラウドの地政学リスク

**Source: Publickey / Bloomberg / Reuters (2026-03-16)**

3月1日に始まった中東武力紛争で、**AWSのUAE・バーレーンリージョンがドローン攻撃を受け、クラウドサービスが中断**した。イラン側もデータセンターへの攻撃を実行。歴史上初めて「データセンターが明確な軍事目標」となった紛争として記録される。

**構図の整理：**

- **湾岸岸沿いに集中するリージョン**：AWS UAE・バーレーン、Azure イスラエル・カタール・UAE、Google Cloud サウジ・カタール
- **物理攻撃の波及**：電力・冷却設備破壊 → クラウドサービス停止 → 国際的な業務影響
- **長期化リスク**：紛争が続くほど周辺リージョンへの攻撃拡大の可能性

**インフラエンジニアが今考えるべきこと：**

「マルチリージョン」はAZ障害の話だけではなくなった。地政学リスクを含めたリージョン選定、**クリティカルシステムの中東依存度の棚卸し**、マルチクラウド/オンプレミスとのフェイルオーバー設計を今一度見直す契機。自分が担当するシステムがどのリージョンに依存しているか、確認しておきたい。

## 4. Cloudflare Custom Regions — データ主権への回答

**Source: Cloudflare Blog (2026-03-18)**

Cloudflareが**Custom Regions**を発表。Regional Servicesを拡張し、顧客が**データ処理の地理的境界を自分で定義**できるようになった。事前定義リージョンの拡充に加え、完全カスタム境界の設定も可能。

**具体的に何が嬉しいか：**

- **GDPR/各国データローカライゼーション法への対応が柔軟に**：「EU域内のみ処理」「日本国内のみ」といった条件を細粒度で設定
- **コンプライアンス作業の削減**：監査・証明書類の簡略化につながる
- **パフォーマンスとの両立**：地理的制約をかけつつCloudflareのネットワーク最適化も活用

**日本での文脈：**

医療情報・個人情報を扱うシステムで「国外持ち出し不可」の要件があるケースに直撃する機能。介護・医療分野のインフラを検討する際には具体的に評価する価値がある。

## 5. AWS Load Balancer Controller — Kubernetes Gateway API が GA

**Source: AWS Japan Blog (2026-03-19)**

AWS Load Balancer ControllerがKubernetes Gateway APIのサポートを**一般提供（GA）開始**。従来のIngress/Serviceリソースに加え、標準のGateway APIを使ってALB/NLBをプロビジョニングできるようになった。

**変わること：**

```yaml
# 従来（Ingress）
apiVersion: networking.k8s.io/v1
kind: Ingress
metadata:
  annotations:
    kubernetes.io/ingress.class: alb
# ↓ Gateway API
apiVersion: gateway.networking.k8s.io/v1
kind: Gateway
metadata:
  name: my-gateway
spec:
  gatewayClassName: alb
```

- Ingress注釈（annotation）だらけの設定から脱却できる
- HTTPRoute/GRPCRoute等で**トラフィックルーティングが宣言的**に書ける
- マルチクラスタ・マルチテナント構成での管理が整理しやすくなる

EKSをすでに運用している環境では段階的に移行を検討してよいタイミング。

## 6. 【セキュリティ】IPA「情報セキュリティ10大脅威2026」— AIリスクが組織編で初ランクイン

**Source: IPA / トレンドマイクロ解説 (2026-03-17)**

IPAが発表した「情報セキュリティ10大脅威2026（組織編）」で、**「AIの利用をめぐるサイバーリスク」が初めて3位**にランクイン。シャドーAI・誤情報の利用・AIを悪用した攻撃の巧妙化が論点。

**組織編 トップ5（抜粋）：**

1. ランサムウェアによる被害
2. サプライチェーンや委託先を狙った攻撃
3. **AIの利用をめぐるサイバーリスク** ← 初選出

**実務影響：**

「シャドーAI」は実際、現場でChatGPT等に業務情報を入力するケースが問題になっている。インフラ・ネットワーク情報（構成図、設定ファイル）をAIに渡す際のガバナンスルール整備が急務。ポリシーのないまま現場任せにしているなら今が整備のタイミング。

## 🛠 今週のツール / Tips

**`wasmer run`でローカルNode.jsをWasmサンドボックスで試す**

Edge.jsをローカルで試したい場合、Wasmerのインストール後に以下で既存のNode.jsプロジェクトをサンドボックス実行できる（まずは実験用途で）：

```bash
# Wasmerインストール
curl https://get.wasmer.io -sSfL | sh

# Node.js互換ランタイムで実行
wasmer run wasmer/node -- node app.js
```

本格的なEdge.js利用は[edgejs.org](https://edgejs.org/)のドキュメントを参照。MCPサーバーやAPIサーバーのサンドボックス実行として面白い使い道がある。
